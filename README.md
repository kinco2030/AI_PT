# AI PT 트레이너

웹캠으로 스쿼트·팔굽혀펴기·윗몸일으키기를 분석하는 Windows용 로컬 앱입니다.
브라우저에 운동 안내, 횟수, 세트, 휴식, 운동 기록과 통계를 표시합니다.

## 실행 환경

- Windows x64, Python 3.12, 웹캠
- `uv`로 Python과 라이브러리를 관리합니다.
- 최초 환경 설치에는 인터넷이 필요합니다. 모델이 없으면 Google에서 내려받습니다.
- 한국어 음성 안내에는 Windows에 설치된 한국어 음성이 필요합니다. 음성을 꺼도 화면 안내는 사용할 수 있습니다.

## 설치와 실행

이 파일과 `app.py`, `pyproject.toml`, `uv.lock`이 있는 저장소 루트에서 실행합니다.

```powershell
uv python install 3.12
uv sync --locked
uv run --locked python app.py
```

첫 설치 후에는 마지막 명령만 실행하면 됩니다. 브라우저가 자동으로 열리고,
터미널에도 `http://127.0.0.1:포트번호` 주소가 표시됩니다. 포트는 매번 달라질 수 있습니다.
카메라는 Python/OpenCV가 직접 열기 때문에 Windows의 데스크톱 앱 카메라 접근이 허용되어야 합니다.

다른 카메라를 사용하거나 브라우저를 직접 열려면 다음과 같이 실행합니다.

```powershell
uv run --locked python app.py --camera 1 --port 7860 --no-browser
```

위 명령의 화면 주소는 `http://127.0.0.1:7860`입니다. 포트가 사용 중이면 다른 번호를 지정합니다.
종료할 때는 화면의 **운동 종료 및 저장**으로 기록 저장을 확인한 뒤 터미널에서 `Ctrl+C`를 누릅니다.

## 파일 구성

- `app.py`: 새 앱의 실행 파일. 운동 규칙, 루틴, 기록, 카메라, 화면이 구역별로 들어 있습니다.
- `pyproject.toml`: 직접 의존성과 Python 범위. Python은 `>=3.12,<3.13`으로 제한합니다.
- `.python-version`: `uv`에서 사용할 Python 3.12.
- `uv.lock`: 직접·간접 의존성의 정확한 버전. Git에 함께 올립니다.
- `vision/`, `test_vision_local.py`, `src/ai_pt/`: 이전 코드 보존. 새 앱이 이 엔진을 호출하지는 않습니다.
- `models/pose_landmarker_lite.task`: 기존에 추적하던 모델. 새 앱은 체크섬이 맞으면 이를 읽어 로컬 저장 폴더에 복사합니다.
- `ai_pt_trainer_files/`: 새 앱이 만드는 로컬 모델, 운동 기록, 캐시. Git에서 제외합니다.

기존 `ai-pt` 명령은 `Hello from ai-pt!`만 출력하는 예제였으므로 새 설정에서 제거했습니다.
시작 명령은 `uv run --locked python app.py`입니다.

## 저장 위치와 Git 제외

기본 운동 기록: `ai_pt_trainer_files/data/workouts.csv`.
로컬 모델: `ai_pt_trainer_files/models/pose_landmarker_lite.task`.
`AI_PT_TRAINER_HOME` 환경 변수로 저장 위치를 바꿀 수 있습니다.
저장 위치를 저장소 안의 다른 폴더로 바꾸면 그 폴더도 `.gitignore`에 추가해야 합니다.

`.venv`, 기록, 캐시, 로그, `.env`는 업로드하지 않습니다. 이미 Git에 올라간 파일은
`.gitignore`를 추가해도 추적이 해제되지 않습니다. 기존 `models`는 이번 전환에서 계속 보존합니다.
파일 읽기·저장 오류가 나면 CSV를 열어 둔 Excel 등 다른 프로그램을 닫고 재시도합니다.

## 사용 조건과 판정 한계

이 앱도 머리·어깨·골반·무릎·발목과 옆모습 위치 가이드를 사용합니다.
부분적인 신체만 보여도 시작되는 앱으로 변경된 것은 아닙니다.
위치 확인 후 약 3초 동안 자세를 유지해야 시작합니다.
가이드에 들어가지 못하면 방의 촬영 거리, 카메라 높이와 각도부터 확인합니다.

화면의 동작 인정률은 **인정 횟수 / 판정한 동작 횟수**입니다.
추적이 끊긴 시도와 종료 시 진행 중이던 시도는 분모에서 제외합니다.
모델의 인식 정확도나 운동 자세 전반을 검증한 수치가 아닙니다.
스쿼트·팔굽혀펴기와 윗몸일으키기의 횟수 인정 시점도 다릅니다.
고정된 각도·위치 기준이 사용자와 촬영 환경에 적합한지는 실제 영상으로 확인해야 합니다.

여러 탭이 하나의 카메라·운동 상태를 공유합니다. 한 PC의 한 사용자·한 탭 사용을 기준으로 합니다.
현재 서버는 `127.0.0.1`에만 연결합니다.

## 변경 사항을 검토할 때

1. 다른 카메라 앱을 닫고 앱이 브라우저에서 열리는지 확인합니다.
2. 세 종목을 각각 2회·1세트로 설정해 시작, 횟수, 완료를 확인합니다.
3. 얕은 동작, 추적 끊김, 다시 들어오기에서 횟수가 임의로 증가하지 않는지 확인합니다.
4. 2세트·짧은 휴식으로 세트 전환과 다음 운동 전환을 확인합니다.
5. 중간 종료와 완료 후 기록을 확인하고 앱 재실행 후에도 기록이 남는지 확인합니다.
6. 음성 끄기, 한국어 음성 없음, 카메라 사용 중 오류를 확인합니다.
7. 가능하면 다른 팀원 PC에서 새로 설치해 반복 확인합니다.

화면과 모델 초기화가 통과해도 실제 카메라에서 동작 판정이 검증된 것은 아닙니다.
가이드 진입 실패, 반복 오집계, 저장 실패가 재현되면 먼저 수정하고 병합을 보류합니다.

## GitHub Desktop으로 전환

이 교체 파일은 준비 당시 로컬 저장소의 `0b4b8ed` (`vision setting`)을 기준으로 만들었습니다.
`Fetch/Pull` 뒤 다른 팀원이 설정 파일을 바꿨다면, 그 변경과 비교하여 필요한 내용을 합친 후 적용합니다.

1. 기존 `AI_PT`를 선택하고 `Changes`를 확인합니다. 미저장 변경을 버리지 않습니다.
2. `main`에서 `Fetch origin`, 필요 시 `Pull origin`을 누릅니다.
3. 필요하면 `backup/before-dashboard` 브랜치를 만들고 `Publish branch`로 기준 버전을 남깁니다.
   브랜치는 커밋된 파일을 보존합니다. 무시된 개인 기록 등은 별도로 백업합니다.
4. 다시 `main`에서 `feature/new-ai-pt` 브랜치를 만듭니다.
5. 준비한 여섯 파일만 루트에 복사합니다. `.git`, `vision`, `models`, `src`는 지우지 않습니다.
6. 설치·실행과 위의 실제 카메라 확인을 진행합니다.
7. `Changes`에서 `app.py`, `pyproject.toml`, `.python-version`, `.gitignore`, `README.md`, `uv.lock`을 확인합니다.
   불필요한 대량 삭제나 개인 기록, `.venv`가 포함되어 있으면 업로드 전에 정리합니다.
8. `Commit to feature/new-ai-pt` → `Publish branch` 또는 `Push origin` → `Create Pull Request`.
9. GitHub의 대상은 `main`, 비교 브랜치는 `feature/new-ai-pt`인지 확인합니다.
   실시한 확인과 아직 확인하지 않은 항목을 PR 설명에 나누어 적습니다. 미검증이면 Draft PR로 공유합니다.
10. 팀원이 확인한 뒤 병합합니다. 충돌이 나면 설정·잠금 파일을 덮어써서 없애지 말고 차이를 검토합니다.

권한 때문에 브랜치를 업로드하지 못하면 저장소 쓰기 권한을 받거나 포크에서 브랜치를 업로드해
원본 저장소로 PR을 만듭니다. 강제 푸시나 `main` 초기화는 이 절차에 필요하지 않습니다.

되돌릴 때는 앱을 종료하고 변경을 커밋/보관한 후 `main`으로 전환하여 `uv sync --locked`를 실행합니다.
브랜치 전환은 무시된 운동 기록까지 되돌리지 않습니다. 기존 앱과 새 앱의 CSV 형식을 섞지 않습니다.

## 의존성을 변경할 때

자동 패키지 설치와 특정 작성자 PC 경로는 `app.py`에서 제거했습니다.
`pyproject.toml`을 바꾸면 `uv lock`으로 잠금 파일을 갱신하고 두 파일을 함께 검토합니다.
그 뒤 `uv sync --locked`로 설치합니다. `--frozen`은 설정과 잠금 파일의 일치 여부를 확인하지 않으므로
처음 환경을 옮기거나 의존성을 바꿀 때 오류를 피하는 용도로 사용하지 않습니다.

`opencv-python`과 `opencv-contrib-python`은 같은 `cv2` 영역을 사용하므로 함께 설치하지 않습니다.
이 앱의 환경은 `opencv-contrib-python` 한 종류로 맞춥니다.

## 교체 파일의 확인 범위

2026-11-27, 원본 저장소를 변경하지 않은 별도 복사본에서 확인했습니다.

- 원본 1,729줄과 교체본의 Python 문법 검사 통과.
- 운동 판정·루틴·기록·카메라·화면 함수/클래스의 내용은 원본과 동일함을 비교 확인.
- Windows x64 Python 3.12.14에서 잠금 파일 생성과 라이브러리 설치 통과.
- 기존 모델의 SHA-256 일치, 모델 재사용, MediaPipe의 빈 영상 추론 통과.
- FastAPI/Gradio 기본 페이지, 화면 구성과 대기 이미지 응답 확인.
- 비어 있는 기록 화면, CSV 저장·재읽기·중복 방지, 통계 그래프 생성 확인.

웹캠을 켠 실제 운동, 한국어 음성 출력, 다른 팀원 PC에서의 동작은 아직 확인하지 않았습니다.
실제 촬영에서의 시작 조건과 횟수 판정이 확인되기 전에는 병합 완료안으로 취급하지 않습니다.
